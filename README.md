Design Rationale 

For this database I created a simplified data model that covers a small Nonprofit animal shelter, specifically for dogs. For this animal shelter, there are 6 entities. The main entities being Persons and Dogs. For the persons, there are subentities of employee, adopter, and foster. A Person can belong to multiple entities, for example, one person can be an employee, adopter, and a Foster at the same time. The Adopter and Foster entities both have relations with the Dog entity. With the adopter, they will be adopting the dog. The foster will be fostering the dog until it is adopted. Every dog must have a Foster home, while pending being adopted. Further information on the dogs on the database is found on a Medical Record table. Many of the tables and data points I have included in this database were influenced by https://www.shelteranimalscount.org/, which is another animal rescue database available online. Although not as in depth as some of the websites databases, I feel like the database schema I have proposed covers the necessities of a Nonprofit animal shelter. 
When it comes to data input for the database, I would implement a view for the entity, Employee, as they would be the only member of the organization which would be inputting data into the database. I would enforce data integrity by only allowing the proper data to be inputted for the appropriate fields.
